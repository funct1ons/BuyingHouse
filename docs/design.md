# 阶段0–3设计（历史）

已完整阅读prompt.txt 2030行。本轮完成完整系统与自动经济模拟；明确不进入正式UI阶段。

## 冻结规则（延续阶段0–1）
- 金额以分为最小单位，使用安全整数。标准初始300000分；52周，初始第1周即可交易。第52周按钮改为结束本年，不生成53周。引擎结算不强制出售，按末周市值计库存，结局只依据实际购房。
- 买入手续费向上取整1%，计入持仓总成本；卖出手续费向上取整1%，已实现利润=净回款−分摊成本。部分出售按floor(总成本×出售量/原数量)分摊，清仓带走全部余数；均价仅派生。
- 初始容量20，不同商品大小不同。无借贷。负面个人事件扣款=min(现金,应付)，未支付部分记入困难，不生成负现金或隐性债务。
- 住房仅一套，允许升档，按旧房原购买价全额抵扣，降档/同档禁止。住房价格固定（随难度调整），无卖房入口，不产生套利；买房不结束游戏。资产含现金、库存市值、住房购买价。
- 仓储升级按累计租赁投入差额收费，不能降级；投入不可变现，不计资产。容量由仓储等级决定，存档不能任意改容量。
- 周顺序：推进周→季节/宏观→事件到期与抽取→趋势→行情→个人收支→新闻→统计→存档通知。事件修正目标价而非重复乘当前价，避免无意复利。
- 趋势惯性、季节目标、宏观目标、事件目标、轻量冲击与均值回归，不是独立随机抽价。不添加工资、贷款、利息或额外资产模型。

## 阶段2数据
20种商品，生活6、电子4、贵重3、季节3、应急4；配置具有name/category/description/basePrice/minPrice/maxPrice/volatility/trendSensitivity/eventSensitivity/unitSize/icon/season/phase。为保持旧API，base/min/max/size明确作为相同数值别名。黄金紧凑昂贵但低波动；显卡/藏品高波动；空调大体积；羽绒服/空调季节反向。参考价与波动属性公开，玩家可查商品说明；绝非内部趋势或未来行情。

40个数据事件：32市场、8个人。市场每周42%概率尝试一个事件，2–4周持续，不叠加相同id；到期移除，目标效应按商品eventSensitivity缩放。个人每周8%概率，约一年4次，标准现金影响90–250元，难度只放大负面金额，避免随机生活收入替代交易。

新闻分可靠消息（已经发生的供需消息）、一般新闻（事件观察，影响不确定）和不驱动市场的未核实传闻。不把消息等级标成“价格预测命中概率”：可靠事件存在也不保证未来价格方向，传闻随机生成可真可假。市场事件的新闻不会暴露内部修正幅度/到期周/RNG/趋势。

五住房标准6500/10000/14000/19000/25000元，区域/描述/结局有差别，当前只有调试图标，最终原创插画留阶段5。四仓储容量20/40/75/120，累计租赁投入0/700/2200/5000元。三难度：

## 状态与统计
GameState保存version/rulesVersion/seed/difficulty/week/cash/inventory/market/warehouse/capacity/house/activeEvents/rng/news/stats/history/result；settings有意与游戏分离，不存入GameState，防止导入陌生档改变本机自动保存设置。

统计：含费总购买额、净销售额、毛交易额、手续费、已实现利润、每商品利润、交易次数、最大盈利/亏损、生活收入/实际支出/困难、仓储投入/升级次数、首次购房周、最高资产和最大回撤。历史记录每周末现金/库存市值/住房价值/资产；同一周交易更新该周点。峰值和最大回撤在每个成功操作后更新（因此可含周内临时高点），回撤存百万分率整数。结算还记录未实现利润、最赚/最亏商品、完整曲线；空交易时商品收益同为0，排序按配置稳定，不作“实质最佳”承诺。

## 技术与兼容
经典defer脚本按依赖加载，window.HomeYear命名空间；无网络、无fetch、无ES模块HTTP要求。引擎无DOM/localStorage依赖。配置、数学、市场、交易、统计、校验、调度、存档、UI分文件；不使用难读单行原型。

随机流market/events/visual从seed分别初始化，状态随GameState保存；模拟policy使用独立随机流。恢复后未来轨迹一致，visual流不影响行情。

操作复制状态→执行→记录→校验→提交。失败不改原状态；revision+token阻止过期界面和重复交易；结算重复操作幂等。restore在复制前校验原对象，防止NaN经JSON静默转null。强制必需字段和准确商品键集合、有限值与安全整数、库存成本关系/容量档级、市场历史长度与当前/前价、52点周历史和资产恒等式、本周季节、事件起止/持续时长/去重、收支利润、结算内容一致性。不能加载缺字段、异常JSON、旧/未来版本。校验不是密码学反作弊；手动构造自洽的历史/收支档仍可能通过，单机游戏不承诺防篡改。

`Engine(seed,difficulty)`沿用snapshot/restore/dispatch/onCommit，增加warehouse操作与visible投影；simulation只用visible，不读取隐藏趋势/activeEvents/rng/未来价格。住房/仓储价格辅助函数统一难度计算。

## 存档策略
SAVE_VERSION=2、规则版本0.2；存档键homeyear.save.v2；设置键homeyear.settings.v1。阶段1无持久化，导出过的v1明确拒绝，无猜测式迁移。配置数据哈希记录在经济报告以复现中间数值版本，不保证中间开发档向最终阶段2兼容。

SaveAdapter.load/save/remove/import/export；失败返回{ok:false,error,recoverable}。import先解析/完整校验，再restore，失败内存不变；成功导入不立刻写localStorage。onCommit自动保存覆盖买卖/住房/仓储/周推进/结算。默认自动保存开，关闭仍可手动保存。

读取损坏或不兼容的原文后隔离，阻止所有普通保存，直到用户确认覆盖或删除。原文可下载。存储拒绝/配额满不回滚游戏状态，可直接导出JSON；未保存状态明确提示。设置字段严格校验，损坏使用默认autoSave=true/sound=true/music=false/animation=normal/numberFormat=decimal，提示恢复默认；仅用户改设置才持久化新设置。file:// localStorage隔离政策随浏览器，JSON导出作为可靠迁移备份。

## 阶段3测试方法
五策略×三难度，每组1000主样本加1000留出样本，共30000最终局。策略只访问Engine.visible与同样公开的商品指南；不知未来行情，不可读取内部trend/隐藏事件效应。所有价格/周进度/事件/买卖/房屋/仓储来自生产引擎，同样的原子校验，没有另造经济模型。

各策略固定卖买阈值；共同住房政策：现金够最低房即购买，末周清仓（idle无仓）然后按现金与旧房抵扣买最高可负担档。这只是模拟决策，不改变引擎“结算不强制卖出”。容量使用80%以上且现金超过升级差额2倍、38周前升级（random还需25%抽签）。具体代码和策略字符串保存在report。

报告包括成功率、资产P10/P50/P90、六种住房分布（含租房）、胜者首次购房周数、仓储升级率/次数、20商品利润贡献、最大回撤分位与逐种子结果。最终留出prefix预先固定，在最终参数之后运行，不用于再次调参；中间validation不冒充最终留出。
