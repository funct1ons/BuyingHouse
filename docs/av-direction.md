# 视听升级方向（已审核并实施）

状态：设计已审核并于 2026-10-03 实施，未修改经济核心、存档协议或旧测试断言。来源与授权见 `docs/av-sources.md`；实施结果见 `docs/art.md`、`docs/av-visual-report.md`、`docs/audio.md`、`docs/av-audio-report.md`。与本稿不同的实施修订：① development 迟滞改为进入 0.90/退出 0.80（见 3.3）；② 画面阶段复用 `HomeYear.AudioDirector` 的逻辑目标；③ setScene 的 climate 取 `hot/steady/cold`。所有音频指标都是数字测量，**不代表人工听感**。

## 0. 边界与不变量

- 仍为纯静态：`index.html` 直接双击（file://）与 GitHub Pages（`.github/workflows/pages.yml` 只复制 `index.html css js assets`）都必须可用。只用经典 `defer` 脚本，不用 fetch、ES 模块、CDN、外部字体或运行时第三方库。
- **不动**：`js/data.js` 经济数据、`math/market/trading/statistics/validation/game/save.js`、存档键与 `homeyear.settings.v1` 结构（`validateSettings` 严格校验键集合，新增设置键会让现有设置被判损坏）。新的视听偏好如需持久化，照 `homeyear.audio.volume.v1` 的做法用独立键。
- 音乐与画面只读 `engine.visible()` / `HomeYear.UI` 已公开的信息，**不得读取 RNG、趋势、隐藏事件**，也不得消耗游戏 RNG（表现层随机数用独立 PRNG，按会话种子派生）。
- 保持 `HomeYear.Art.icon/scene/palette/iconIds/sceneIds` 与 `HomeYear.Audio.unlock/configure/volume/setVolume/status/play` 的签名；只做向后兼容的新增。
- 现有 data-testid、data-action 不改名。

## 1. 现状诊断（为什么要重做，而不是“加阴影”）

- `js/art.js`：8 色纯平填充，几何块拼接，无光源、无材质、无景深；`backdrop()` 被所有场景共用，五套住房构图相似；租房状态复用 `house-0`（老旧单间），视觉上把“还在租房”和“已买第一套房”画成一样。
- `js/audio.js`：16 个 sine 单音、650ms 定时器、单声部，峰值约 0.009（≈−41 dBFS，见 `docs/audio-diagnostic.md`），无和声、无低音、无段落、无阶段变化。已知 bug：设置 change 时没有在可信手势内 resume，可出现 `musicRunning=true` 但无信号。
- `js/ui.js` 每次操作 `app.innerHTML` 整体重建，场景 SVG 每次都重新解析。插画变丰富后这会成为性能瓶颈。

## 2. 视觉方向：温暖都市 · 成熟纸本插画

关键词：**傍晚的窗光、旧街的砖与梧桐、纸张颗粒、克制的金色**。成熟感靠的是光影层次、材质和生活细节，而不是更饱和的颜色或更多圆角。

UI 设计 token 在现有 `--bg/--surface/...` 上扩展：`--paper-grain`、`--elev-1/2/3`（双层阴影：环境+主光）、`--ink-strong`、`--brass`（#b88a4a，用于目标/钥匙）、`--phase-tint`（随阶段变化的极淡背景色）。数字一律 `font-variant-numeric: tabular-nums`。字体仍只用系统字体栈（`"Microsoft YaHei UI","PingFang SC","Noto Sans SC",sans-serif`）；标题字标改为原创 SVG 徽记（钥匙 + “家”字印章轮廓）+ 系统字，避免下载字体。

### 2.2 材质与技术做法

- **共享 defs**：渐变、图案、裁剪统一放进 `art.js` 启动时插入的一个隐藏 `<svg>`，ID 一律 `hy-` 前缀（如 `hy-brick`、`hy-sky-dusk`、`hy-glow`）。场景只引用，不自带 ID，彻底解决多次内联的 ID 冲突。`assets/build-art.cjs` 的检查从“禁止 id=”改为“场景内禁止 id=，引用只能是 `url(#hy-…)`”，导出独立 SVG 时把 defs 嵌入文件。
- **纸纹/墙面颗粒**：启动时用 canvas 生成一张 256×256 噪声贴图并转 dataURL（file:// 下 canvas 不被污染，可用），作为 CSS 背景以 `mix-blend-mode: multiply`、不透明度 0.05–0.08 叠加在面板与插画上。**不在大面积或动画元素上用实时 SVG 滤镜**（`feTurbulence` 只在开发期用来调参）。
- **砖、瓦、木地板、百叶**：小尺寸 SVG `pattern`，2–3 色。
- **窗光**：径向渐变辉光 + 窗内剪影（窗帘、台灯、绿植）；入夜时点亮比例随阶段升高。
- **大气透视**：远景天际线降饱和、提亮、去细节；中景完整细节；前景用深色剪影压边框，形成景深。

### 2.4 各画面设计

- **开始页**：全幅黄昏城市（`preserveAspectRatio="xMidYMax slice"`），三层视差（远景/中景/前景，跟随鼠标位移 ≤8px，减少动效时关闭）；≤12 扇窗以错开时间缓慢亮起（只动 opacity）。表单为带纸纹的悬浮卡片，标题徽记。
- **市场主界面**：左栏“我的窗口”显示当前住所（未购房显示 `rent`），按季节与阶段换时段光；顶栏周数做撕页日历，剩余周数在第 45 周起变为黄铜色倒计时环（不用红色警报）。商品卡加品类色签、价格涨跌用细色带而非整卡染色；暴涨/暴跌只做一次 600ms 边缘光。右栏“城市来信”做成信笺：可靠＝朱红印章、一般新闻＝蓝色邮戳、市场传闻＝铅笔批注。
- **交易对话框**：左侧商品放大到 120px 并放在货架/柜台小场景上；走势图加网格、面积渐变和“持仓均价”虚线；右侧预览做成小票样式（锯齿边、等宽数字）。
- **住房**：房产传单式卡片（插画 + 区位标签 + 价格 + 抵扣/应付）；已拥有盖“已入住”章。**购房庆祝**是全游戏最强反馈：全屏遮罩 → 门向内打开（SVG scaleX）→ 室内暖光溢出 → 钥匙闪光 → canvas 彩纸 ≤120 粒子、2.5s 后自动停止 rAF；减少动效时只淡入插画与文字。
- **年度结算**：绘本跨页：左页最终住所（成功＝金色时刻，未购房＝蓝调时刻租房窗里仍亮着一盏灯），右页账本式统计；资产曲线标注首次购房周与峰值。

### 2.5 阶段视觉映射

由 `body[data-phase]` 与 `body[data-season]` 驱动 CSS 变量，阶段定义与音乐共用（见 3.2），确保“看到的”和“听到的”同步。

## 3. 音乐方向：分阶段互动配乐

### 3.1 总体做法

- 纯 Web Audio 实时合成（不引入音频文件与库）。原因：项目约定不用 fetch，file:// 下用 fetch/XHR 读本地音频文件不可靠；把音频以 base64 嵌进 JS 可行但体积大；`<audio>` 元素能播放，但很难做小节对齐切换，而且 file:// 下接入 `MediaElementSource` 的行为（是否被视为跨源）**本轮未验证**，实施前需要实测。
- **横向**：按阶段切换不同编曲（不同调性、速度、配器）；**纵向**：同一曲内按进度/景气增减声部层。
- **主导动机“家”**：音阶级数 3–5–6–5–1̇（D 大调为 F♯–A–B–A–D），在每首曲中以不同乐器、节奏、调式变形出现，让整年听起来是同一个故事。
- 每首 32 小节（A8 / B8 / A′8 / C8），循环时由表现层 PRNG 从每段 2–3 种变体中挑选（和弦转位、旋律装饰、鼓过门、层的进出），避免听腻；不同声部用不等长循环（如 32 拍旋律对 24 拍琶音），借鉴系统音乐的相位错开思路（Parviainen 文章）。

### 3.2 公开状态 → 曲目映射

输入只用：`HomeYear.UI.screen()`、对话框是否打开、`visible()` 的 `week / status / house / cash / season`、景气标签（偏热/平稳/偏冷，与 UI 显示同一阈值）以及用公开辅助函数算出的“距下一套住房的现金进度”`p`。

| 曲目 | 条件（自上而下优先） | 调性 / BPM / 拍号 | 和声骨架 | 配器与声部 |
|---|---|---|---|---|
| `menu` 窗台夜灯 | `screen==='start'` | D 大调，72，4/4 | Imaj7–IVmaj7–vi9–V7sus4 | 毛毡钢琴主旋（动机完整呈现）、暖垫音、低音长音、极轻磁带底噪 |
| `early` 出租屋的早晨 | 游戏中、`status==='playing'`、week ≤ 17、未购房、`p < 0.90`（已在 development 时为 `p < 0.80`） | F 大调，92，4/4 轻摇摆 55% | I–vi7–ii7–V7sus | FM 电钢琴和弦、拨弦贝斯、刷沙锤、马林巴副旋律（动机碎片） |
| `development` 街区在发光 | 游戏中、week 18–44，或已购房，或 `p ≥ 0.90`（迟滞见 3.3） | A♭ 大调（相对 F 的三度关系上扬），100 | I–iii7–IVmaj7–V/vi–vi–IV–ii7–V | 步进贝斯、轻底鼓/边击、弦乐垫、钟琴对位、三角波长笛式主旋（动机延展） |
| `sprint` 最后的几周 | 游戏中、week ≥ 45、`status==='playing'` | C 小调 → 副歌转 E♭ 大调，116 | i–VI–III–VII；副歌 IV–V–vi–I | 八分音符闷音拨弦固定音型、木鱼“钟表”、切分贝斯、每 8 小节弦乐渐强；第 51–52 周加一层定音鼓滚奏 |
| `ending-home` 钥匙 | `status==='ended'` 且已购房 | E♭ 大调，84 | IV–V–iii–vi–ii–V–I（结尾变格终止 IV–I） | 钢琴+弦乐+钟琴全编制，动机完整和声化；32 小节后进入 8 小节柔和尾声循环 |
| `ending-rent` 还是那间小屋 | `status==='ended'` 且未购房 | D 大调，66 | I–♭VI–iv–I（借用和弦）→ 最后 IV–I 回到大调 | 独奏钢琴 + 轻垫音；动机先以小调色彩出现，结尾回到大调，苦涩但有希望 |

纵向层（不触发换曲）：`p` 每跨越 0.25 加一层（如副旋律、打击）；景气“偏热”加亮度（滤波上限 +20%），“偏冷”减一层打击。

短音型（stinger，叠在当前曲上，曲目音量先压低 6 dB 再恢复）：购房（当前调 I–IV–I add9 琶音 + 钟声，约 2 小节）、重大新闻、盈利/亏损（与现有 `play()` 共用接口，音高跟随当前调）。

### 3.3 防频繁换曲

- 目标曲目判定每次渲染都做，但**切换只在当前曲的乐句边界（4 小节）生效**；
- 最短驻留：游戏内曲目至少 2 个乐句（约 20–30s）；开始页↔游戏、进入结算不受此限，在下一个小节线切；
- 迟滞：`p` 进入 0.90 才升到 `development`，跌回 0.80 以下才可能退回（实施修订：原稿 0.45/0.35 低于标准难度开局 p≈0.46、轻松 0.77，会让开局直接跳过 early）；画面阶段与音乐共用同一 `HomeYear.AudioDirector.phaseOf` 迟滞，UI 自持一个 director 实例取逻辑目标阶段，不读音频实际 cue；week 阈值单向（周数不倒退），读档时直接按状态定位；
- 对话框（交易/住房/设置）不换曲，只做混音快照：音乐总线低通降到约 2.5 kHz、−4 dB，300ms 过渡；
- 连续点“下一周”时请求只保留最新一次。

### 3.4 平滑切换

- 请求 → 等到下一个小节线 → 旧曲 2 小节内用 `setTargetAtTime` 衰减到 0，同时新曲从“引子”（只有垫音+低音）起步，1 小节淡入；随后正常进入 A 段。
- 速度不同的曲目各用自己的拍子网格，交叉段只让无节奏层（垫音）重叠，避免两套节拍打架。
- 进入结算：在下一拍、1.5s 淡出旧曲，接购房或未购房引子。
- 所有增益/滤波变化都用 AudioParam 斜坡，不直接赋值，防爆音。

### 3.5 音色设计（原创合成配方）

- 毛毡钢琴：2–3 个略失谐分音 + 5ms 起音 + 随音高缩短的指数衰减 + 力度控制的低通 + 极短高通噪声作琴槌声。
- FM 电钢琴：正弦载波/调制 1:1，调制指数随时间衰减。
- 暖垫音：两只失谐锯齿波 → 低通 900 Hz，1.2s 起音，慢速 LFO 合唱。
- 弦乐：3 只锯齿波 ±7 音分 → 低通，300ms 后加入 5 Hz 揉弦。
- 马林巴/钟琴：正弦 + 非谐泛音快速衰减。
- 拨弦/贝斯：锯齿/三角 + 快速滤波包络。
- 打击：底鼓＝正弦下滑；沙锤＝带通 6 kHz 噪声；边击/木鱼＝带通短促点击。
- 空间：运行时生成的 2.2s 立体声指数衰减噪声 IR → `ConvolverNode`，发送量按乐器设置。

### 3.6 调度、总线与生命周期

- 调度：每 25ms 唤醒、前瞻 100ms，用 AudioContext 时钟精确排音（cwilso/metronome 的模式，代码原创）。复音上限 24 个，超出时偷走最老的释放中音符。
- 总线：`各曲目层 → 曲目总线 → 音乐总线（对话框低通 + 压缩器限峰）→ musicGain`，`音效 → sfxGain`，两者都进入现有 `masterGain`（音量滑块），`status().gain` 语义不变。
- **用户手势**：只在可信 click/keydown/change 处理中创建/resume；修复已知 bug——设置 change 应用后在同一事件内调用 unlock。resume 被拒或 1s 后仍非 running 时，显示可点击的“点击启用声音”提示；`musicRunning` 只在“设置开启 + 调度器运行”时为 true（关闭音乐时立即为 false，内部再做淡出），保持现有测试语义并保证单一调度器。
- **静音**：音量 0 → 淡出后暂停调度节省 CPU；恢复 >0 时从下一乐句开始。音乐关闭 400ms 淡出后停调度；音效独立。
- **隐藏页面**：`visibilitychange` 隐藏 → 300ms 淡出、停调度，音效也空闲时 suspend；返回 → resume（失败则显示启用提示）→ 从当前曲的 A′ 段开头 1.5s 淡入，不从头开始。
- `status()` 向后兼容地增加 `cue / section / bpm / pendingCue / lastSwitchAt` 只读字段，供自动化测试。

## 5. 验收标准

### 5.1 画面
- 1366×768、1600×900、1920×1080、2560×1440，外加 1920×1080 在 125%/150% 缩放：开始页、四季 × 各阶段市场页、交易、住房、购房庆祝、两种结算均截图；无页面溢出、遮挡、文字重叠，`next-week` 可见（沿用现有断言）。
- 正文文字对面板背景对比度 ≥ 4.5:1（脚本计算）。
- file:// 打开到开始页首次绘制 < 1s；`renderGame` 中位数 < 16ms（1366）；单个游戏画面 SVG 元素总数 < 2500。
- 空闲 60s（音乐开、无交互）：CDP `Performance.getMetrics` 的 TaskDuration 增量 < 墙钟时间 3%；彩纸 2.5s 后 rAF 停止。headless 数值只作回归基线。
- 现有 `run.cjs / cdp-smoke / ui-interaction / system-browser / acceptance-supplement` 全部不改并通过；平衡 JSON 哈希不变。

### 5.2 音频（数字测量，**不等于真实听感**）
- 每首曲 `OfflineAudioContext` 离线渲染 64 小节，masterGain=1：采样峰值 ≤ −1 dBFS；300ms 窗口 RMS 中位数 −24 至 −18 dBFS；各游戏内曲目间 RMS 中位数差 ≤ 3 dB（`menu` 与 `ending-rent` 允许再低 4 dB）；无直流偏移。
- 音效峰值 ≤ −6 dBFS，且高于音乐 RMS 至少 6 dB。
- 切换：每对相邻曲目（menu→early、early→development、development→sprint、sprint→两种结局、任意→menu）离线渲染切换段，过渡窗内 RMS 下凹 ≤ 6 dB、上冲 ≤ 3 dB，无超过阈值的相邻采样突变（爆音检测）；切换起点与小节线误差 ≤ 5ms。
- 防抖：脚本让状态在 week 44/45、`p` 0.79/0.91 间来回抖动 2 分钟，换曲次数符合驻留规则（每 20s 内 ≤ 1 次）。
- 实时（沿用 `tests/audio-diagnostic.cjs` 的 AnalyserNode 分支）：首次可信点击后 running 且峰值 > 0；切到其他标签 500ms 内为 0；返回 2s 内恢复；关音乐 600ms 内为 0 且调度器停止；音量 0 时为 0；未交互不创建 AudioContext。
- 这些都只证明浏览器内数字信号，不证明扬声器发声或好听。

## 6. 试听样本计划

- 开发脚本在 Edge 中离线渲染：6 首曲各 45s 节选、6 段切换各 20s、3 个短音型，输出 22.05 kHz 单声道 16-bit WAV（每 45s 约 2 MB）到 `docs/av-samples/`，附 `levels.json`（峰值/RMS/切换点）。如仓库体积不合适则输出到系统 TEMP，只提交 levels.json。
- 开发用试听页 `tests/av-preview.html`（tests/ 不随 Pages 发布）：按钮强制切换曲目/阶段/季节、触发短音型、显示 `status()`；必须先点击才发声。
- 人工听感清单（交由用户或维护者实际执行并记录设备）：笔记本扬声器与耳机各一次、音量 50%；是否刺耳/浑浊、低音在小扬声器是否消失、长时间（10 分钟）是否烦、切换是否突兀、音效是否被音乐盖住。在完成人工试听之前，文档一律写“未经人工听验”。

## 7. 风险与取舍

1. **合成音色上限**：纯 Web Audio 合成的钢琴/弦乐无法达到采样乐器质感，“完整有层次配乐”主要靠和声、声部写作、混响和变化来实现。若审核认为不够，备选是离线渲染原创音频为 OGG 放进 `assets/`，以 `<audio>` 元素播放——代价是失去小节对齐切换（只能整曲交叉淡化），file:// 下能否接入 Web Audio 做测量也尚未验证。建议先走合成路线并交付试听样本再决定。
2. **工作量**：手写 6 场景 × 季节附件 + 20 图标重绘 + 6 首 32 小节编曲，是本项目最大的一块；`art*.js` 预计从 17 KB 增至 80–120 KB，仍然可以秒开。
3. **resume 时机**：从隐藏状态返回时 resume 依赖浏览器的“用户激活”判定，个别情况可能被拒——已设计“点击启用声音”兜底，不静默失败。
4. **性能**：卷积混响 + 24 复音在低端笔记本上可能吃 CPU；设复音上限，隐藏/静音时停调度；必要时降为单声道 IR。
5. **信息泄露**：音乐阶段若用了隐藏变量（如原始 macro 数值、未来事件）会给玩家暗示；已限定只用公开字段和 UI 已显示的分档。
6. **测试兼容**：`ui-interaction` 与 `acceptance-supplement` 依赖 `musicRunning` 的即时语义与“单一循环”；新设计保持这两点，实施后先跑旧测试再加新测试。
7. **参考局限**：几份自适应音乐权威文章（Wikipedia、Game Developer、Wwise、FMOD、web.dev）本次未能取回，相关术语按行业通用用法使用，没有附出处（见 `docs/av-sources.md` 失败记录）。
