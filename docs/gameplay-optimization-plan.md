# 玩法优化方案：少量轮换商品、强事件冲击与每周街区快报

状态：用户已授权委托推进；本文件是实施与验收依据，不代表功能已经完成。
基线：`bef4056`（视听升级已上线）；执行方式：主对话只委托、跟踪、审核，Grok 主 worker 负责产品整合和验证。用户后续授权按需开启子代理，覆盖此前“禁止再委托”的限制。子代理应收到精简上下文、明确任务和文件范围，避免重复工作、同文件并发编辑和层层委托；由 Grok 汇总结果并记录代理及收尾情况。

## 1. 目标与问题

用户反馈：商品涨跌太小，不刺激；20 种商品每周全部检查负担大；新周新闻平淡，不吸引注意。

统一目标：**每周少看一些，但看到的更值得决策。** 理想流程是“扫头条 → 处理持仓 → 看两三个新机会 → 买卖或观望 → 下一周”，而不是逐张扫描 20 张卡。

本轮不是只放大随机数，也不是重新制作美术或音乐。保留温暖都市视听、52 周买房目标，同时增加发现机会的兴奋、持仓的牵挂和推进时间后的期待。不会照搬其他游戏的名称、文本、价格表、素材或社会事件。

### 当前代码诊断（实施前基线）

- `js/market.js` 每周仅向目标价移动约 22%；目标价提高 50% 的事件，在初始接近目标价时，当周直接贡献约 11%，事件冲击被摊薄。
- 20 种商品始终可以买卖，周与周之间缺少新到货/缺货造成的经营变化。
- 持续事件每周重复列在新闻中；随机传闻的方向目前没有与未来事件生成关联，认真阅读传闻缺少实际判断意义。
- 当前住房价格建立在旧收益分布上，提高利润空间之后必须重新评估，不允许只改波动、不测目标难度。

## 2. 参考资料与取舍

以下资料在方案提出时已搜索，并实际取回前两篇正文；没有实际试玩参考游戏，不把社区描述当成所有版本的官方规则。

1. 游民星空《买房记玩法指南》：https://www.gamersky.com/handbooksy/201810/1115798.shtml
   - 描述三个市场、有限货物、切换市场耗时一周，同时刷新商品种类与价格；新闻事件改变供需。
2. 触乐《买房记：我的逆袭》评测：https://www.chuapp.com/article/274469.html
   - 描述价格可能因事件降到原价一半或更低；选择抛售还是等待。
   - 同时指出熟悉固定价格区间后玩法容易趋同，这是本项目要避免的缺点。
3. Steam《Space Warlord Organ Trading Simulator》：https://store.steampowered.com/app/1507780/
   - 商店检索说明动态交易市场和货物管理；仅借鉴不同商品有不同经营意义，不引入实时手速压力。
4. Steam《Reigns》：https://store.steampowered.com/app/474750/
   - 商店检索说明简短决策及后续影响；仅借鉴事件表达，不给每周新闻强塞选择弹窗。

核心借鉴：有限信息量、鲜明机会、具体事件和经营取舍。避免纯随机爆赚、死记固定价格区间、无退出通道的强制缺货。

## 3. 首轮必须完成的范围

### 3.1 精简与轮换：12 种商品池，每周 8 种在售

- 新规则商品池为 12 种，每周 8 种可购入；每次推进替换 2—3 种，保留市场连续性，不完全洗牌。
- 筛选基于现有 20 种商品，优先合并定位重叠者；不得只删低价商品或让昂贵小体积品成为唯一最优解。
- 三类商品均有明确经营角色：日常周转品（低本金/相对稳定）、季节与产业品（季节/消息可理解）、投机热点品（高风险高潜在收益）。
- 每周保证低本金可买的商品及风险类别覆盖；保证的是价格门槛，不是无现金玩家自动获得可买资金。
- 轮换采用保存的确定性随机状态；不得每次渲染、重读档或点筛选重新抽样。
- 设可验证的最大连续缺席时长，首轮建议不超过 3 周；不是承诺回归时涨价。若与其他轮换约束冲突，worker 在规则冻结阶段明确调整，不得悄悄破坏约束。
- 不利用玩家隐藏利润、未来行情或未来事件来定向“送机会”或惩罚持仓；新闻关联只改变展示优先级。

### 3.2 不在售商品与退出通道

- 在售商品正常买卖；非在售商品不得买入，必须由引擎校验，不只隐藏按钮。
- 非在售但持有的商品仍显示在库存中，可通过回收渠道出售，初始折价范围 5%—10%，实际采用值要写入规则并经模拟验证。
- 明确显示正常估值、回收报价、折价与费用；同一渠道一周内报价不随 UI 操作变化。折价不是隐藏手续费。
- 玩家可以立即折价落袋，或承担库存占用与未来价格风险等待回归，不被随机缺货锁死。
- 第 52 周仍可交易、购房、选择变现，再显式结束本年；不出现第 53 周。
- 所有持仓均有明确的最后变现路径，不暗中自动卖货。净资产、浮盈、卖出预览与年度结果的估值口径必须一致并向玩家说明，避免用无法成交的估值伪装可支付现金。
- 保留整数分金额、买卖费、部分出售精确成本分摊、清仓余数、原子拒绝及重复操作保护。

### 3.3 分层波动与强事件

以下为首轮调参目标，不是硬保证每周落在区间内；必须报告实际分位数、边界裁剪与价格分布。

| 类型 | 普通周主要波动目标 | 事件冲击目标 |
|---|---|---|
| 日常周转品 | 约 ±5%—12% | 约 ±15%—30% |
| 季节与产业品 | 约 ±10%—22% | 涨 30%—60%；跌 20%—40% |
| 投机热点品 | 约 ±15%—30% | 少数事件涨 60%—120%；或跌 35%—60% |

- 同周只突出少数机会，目标是 1—2 个重点异动，不要求每周固定产生大事件，允许平静周存在。
- 事件机制分开处理：**一次性立即冲击**、有限持续影响、恢复或结构性价格中枢变化。不要把目标价作用重复当成乘数逐周复利。
- 新闻在价格变化后展示已经发生的事实，不能新闻一公布再送一个必赚涨幅；预告不是保证收益。
- 三种下跌原因可区别：短暂清仓可能恢复；产品过时可能改变价格中枢；热点退潮可以反弹也能继续跌。禁止“跌了必买、等几周稳赚”。
- 仍有合理价格上下界、可复现趋势/季节/均值回归；报告长期钉在上下界的比例，不能靠频繁裁剪假造波动。
- 不把全部刺激集中于一种高价商品，不以纯随机毁灭玩家代替决策风险。

### 3.4 每周街区快报

- 新周主界面上方提供快报，按优先级展示：①新头条 ②与持仓有关的变化 ③新到货/暂时缺货。
- 初始页和继续/导入存档不得重复触发新周动画或生成新事件；回看快报不耗周、不重抽行情。
- 标题有具体情境和原因，正文简短；持续事件归到“仍在影响”，不每周伪装新消息。
- 头条带影响商品、真实本周涨跌、是否可买、持有数量、当前可执行卖出净额/盈亏，以及直达交易按钮。
- 例如“港口停摆，进口货一夜难求”“新款突然发布，旧显卡开始甩卖”；最终原创文案以保留商品为准。示例中的涨幅不能硬编码到新闻，必须来自本周真实行情。
- 普通消息不打断操作；重大事件可短暂强化卡片/图标/音效，但可立即继续，不能每周强制关闭弹窗。
- 默认先看持仓、异动、新到货；完整 8 种市场仍可浏览。保留搜索、分类、关注、排序、键盘、交易预览与帮助。
- 新闻中的方向必须区分“已经发生”与“尚未确定”；不得暗示未来行情保证。
- 重大事件提示尊重系统减少动效、游戏动画设置、静音与隐藏标签页；复用现有视听设施，避免新建重复音乐定时器。

### 3.5 传闻：第一轮不得继续误导

- 第一轮至少停用无关联的随机涨跌传闻，或明确改成不承担方向预测的街区闲谈，不将其包装成可交易信号。
- 有未来兑现机制的传闻/预告属于第二轮增强：可兑现、可落空、有明确生成逻辑与事后核验；可靠事件不等于交易必赚。
- 不以未经验证的“准确率”数字当可靠性标签。

### 3.6 住房、仓储与年度目标

- 第一套房是普通玩家可能达成的阶段胜利，中高档需要多次好判断，顶档是优秀经营加运气的挑战。
- 不让涨幅增加变成大多数策略十周内结束追求，也不把所有利润提高用涨房价抵消。
- 新房价和仓储价格/容量只在模拟之后决定；报告买房周数与各档购买率，而非只报告“任意买房胜率”。
- 仓储要体现轮换等待和不同商品体积的取舍，不成为无脑必升或永久无意义。
- 本轮不增加借贷、健康、声望、多城市、实时交易或大型任务树。

## 4. 规则、存档和技术约束

- 原创纯静态 HTML/CSS/经典 defer JavaScript，双击 file:// 与现有 Pages 发布结构均兼容，不新增运行时网络、CDN、ES 模块 fetch 依赖。
- 保留视听升级、用户设置、音量/静音恢复、52 周边界和实际现金购房规则；不得只改 UI 绕过引擎。
- 商品轮换、缺席计数、冲击/结构性状态，以及后续事件链（若实施）均进入版本化存档与严格校验。
- 同版本同种子同操作可复现；完整恢复后未来轨迹一致。表现层随机不得消耗经济随机流。
- **不得悄悄把旧局改成新经济规则，不得丢弃旧存档或持仓。** 规则冻结时给出明确方案并经主审：保留旧规则兼容，或用户确认后迁移并保留可导出的原档备份。若迁移，已删商品持仓须保留可出售渠道或明确等价转换，现金/成本/统计不得凭空改变。
- 迁移提示解释会改变未来走势；拒绝迁移不覆盖旧档。损坏档隔离、存储拒绝、导出兜底仍有效。
- 明确升版策略、旧设置保留和历史数据兼容，不把存档版本不匹配简单当损坏覆盖。
- 新测试应覆盖变化后的规则；旧断言确因商品规模/规则版本失效时可有证据地更新，并逐条记录原因，不得放宽资金/成本/边界/复现断言掩盖回归。

## 5. 第二轮增强（第一轮通过后再审核是否执行）

- 少量跨周事件链：供给冲击→恢复、产品发布→旧品转弱、活动预告→活动结束。
- 有兑现/落空结果的传闻，玩家能逐步认识消息来源，但不能泄露保存的未来结果。
- 年度总结讲述玩家实际经历过的机会与失误，不编造操作或虚构盈利。

第一轮未证明核心玩法改善前不自动扩大这部分；worker 不自作主张把它作为已完成或必须一次性堆入的功能。主审应明确报告实施范围。

## 7. 验收清单

### 引擎与存档

- 每周 8 种在售、12 种池、替换/分类/低本金/最大缺席约束满足；读档与刷新不重抽。
- 缺货不能买，但持仓可明确折价卖；清仓成本精确；第 52 周所有持仓仍有退出通道。
- 立即冲击只生效一次；持续/恢复/结构变化有明确到期及状态，不无意复利、不负价、不溢出。
- 同 seed/操作、保存恢复未来轨迹一致；UI消息查看不消耗随机数。
- 新档严格校验、旧档明确兼容或确认迁移、拒绝迁移/损坏隔离/存储失败/导出恢复均可验证。
- 无预知策略、无同周套利、无一商品永久垄断、无价格上下界长时间钉死、无缺货强制无解。

### UI 与体验证据

- 1366×768、1600×900、1920×1080、2560×1440及合理缩放，市场/快报/缺货库存/交易/结算截图。
- 头条涨幅、持仓、出售预览全部与真实引擎一致，直达交易可用；持续事件不冒充新事件。
- 下一周按钮与核心交易可见；Tab/快捷键/减少动效/音频正常；file:// 无控制台错误、无运行时网络请求。
- 不把“好玩”当自动化可以证明的事实。时间负担目标：玩家几秒内识别重点，少量机会即可完成判断；需要人工试玩才能确认认知负担与情绪起伏。

### 模拟报告

- 胜率、各档住房购买率、首次买房周数、终局资产分布、最大回撤、破产/极低现金概率。
- 商品利润贡献与集中度、策略收益分布、仓储升级率、轮换缺席/回收出售频率。
- 普通周及事件周涨跌分布、极端异动频次、价格边界裁剪率，头条与实际异动一致性。
- 跨 seed/难度是否出现高波动唯一解、近乎随机稳赢或高手也难胜，发现即调参并诚实报告。
