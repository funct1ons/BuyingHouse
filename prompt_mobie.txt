请在现有项目上完成移动端适配，不新建独立 Android 项目。目标是让当前 Web 游戏继续通过同一个 GitHub Pages 链接运行，并同时获得良好的 PC 和 Android 手机浏览器体验。

本次改动以“响应式 UI + 移动端交互适配”为主，尽量保持现有游戏逻辑、数据结构和玩法不变，避免大规模重构。

重点完成：

1. 检查并重新设计响应式布局，使界面能够适配常见 Android 手机屏幕，不出现元素溢出、遮挡、文字过小或比例失衡。
2. 手机端不要简单缩放 PC UI，应根据屏幕尺寸重新安排面板、按钮、信息区和游戏区域的位置。
3. 保持 PC 端现有鼠标、键盘操作，同时增加完整的触摸操作支持；优先使用 Pointer Events 统一 mouse/touch 输入。
4. 所有原本依赖 hover、右键、键盘快捷键、鼠标精确点击的功能，都必须检查是否需要手机端替代操作。
5. 调整按钮、卡牌、格子等可点击区域，使其适合手指操作，并避免误触。
6. 正确配置 viewport，并处理 Android 浏览器的滚动、双击缩放、长按选择文本等可能影响游戏体验的行为。
7. 考虑手机刘海、挖孔屏以及底部手势区域，必要时使用 safe-area。
8. 根据当前游戏界面判断更适合横屏还是竖屏，并做好对应布局；如果屏幕尺寸不合适，可给出友好的旋转提示。
9. 检查手机端性能，避免因为高分辨率 Canvas、过多动画、阴影或 DOM 更新导致明显卡顿。
10. 保持现有 GitHub Pages 部署方式不变，不引入 Android Studio、Flutter、React Native 等额外重型依赖。

完成后请分别检查：
- PC 大屏
- PC 较小窗口
- Android 常见竖屏尺寸
- Android 常见横屏尺寸

验收标准是：同一套代码在 PC 和 Android 浏览器中均可完整游玩，主要 UI 无遮挡/溢出，触摸操作自然，PC 原有功能不退化。

如果发现现有代码结构不利于移动端适配，可以做必要的小规模重构，但优先采用最小改动方案。
