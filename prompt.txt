你现在负责从零设计并实现一款完整、可玩的 PC 单机经营策略游戏。

## 一、项目目标

开发一款以“在有限时间内通过商品交易赚钱，最终买下住房”为核心目标的单机经营策略游戏。

玩法参考经典手游《买房记》：

- 玩家拥有少量初始资金；
- 游戏按“周”推进；
- 每周市场中的各种商品价格都会发生变化；
- 玩家观察价格，在低价时买入商品；
- 在未来价格上涨时卖出；
- 通过商品价格波动赚取差价；
- 玩家库存容量有限，需要管理现金与库存；
- 可以通过部分投资或升级提高经营能力；
- 随机事件会影响商品价格或玩家经济状况；
- 一局拥有明确的时间限制；
- 最终目标是在规定时间内积累足够资产购买住房。

目标不是制作一个只有数字按钮的 demo，而是制作一个：

**玩法完整、数值有策略性、美术完成度较高、可以长期反复游玩的正式小游戏。**

重点复刻《买房记》这一类游戏的核心体验和经营节奏，但不要直接复制原游戏的名称、图片、音效、文本、美术素材或独有 UI。

可以参考其玩法机制，但游戏名称、美术、商品图片、文案、界面风格等应自行设计。

# 二、技术栈

这个项目最重要的工程原则是：

> 轻依赖、轻环境、可离线、易维护。

采用：

- HTML5
- CSS3
- Vanilla JavaScript
- SVG / CSS 绘制 UI 与简单图标
- localStorage 存档
- Web Audio API 或本地音频文件负责音效
- 可选 PWA

禁止为了这个项目引入不必要的复杂环境。

原则上不要使用：

- React
- Vue
- Angular
- Electron
- Unity
- Godot
- Node 后端
- 数据库
- npm UI 框架
- 大型第三方运行时

项目最终应该是一个纯静态 Web App。

理想情况下：

```text
index.html
css/
js/
assets/
manifest.json
sw.js
README.md
```

即可构成整个游戏。

游戏必须可以：

1. 在 Windows Chrome / Edge 中运行；
2. 完全离线运行；
3. 不需要服务器或账号；
4. 不需要联网；
5. 不依赖 CDN；
6. 所有素材均保存在项目目录；
7. 关闭游戏后可以继续读取存档。

开发测试时可以使用：

```powershell
python -m http.server 8000
```

但不要让 Python 成为游戏本身的运行依赖。

如果能够兼容直接打开 `index.html`，尽量兼容。

因此不要设计必须依赖 HTTP fetch 才能读取的核心数据文件。

商品配置等可以直接定义在 JavaScript 数据模块中。

# 四、核心游戏设定

请自行为游戏设计一个原创名称。

背景设定可以是：

> 玩家刚进入城市生活，手上只有少量积蓄，希望在一年之内买下一套自己的房子。
>
> 单靠工资显然不够，因此玩家开始利用不同商品价格的周期性波动进行交易。

整体风格可以带一些轻松幽默的都市生活气息。

例如：

“距离拥有自己的家，还有 52 周。”

游戏周期：

```text
52 周
```

代表一年。

初始：

```text
现金：3000
周数：第 1 周
库存容量：有限
房屋目标：一套普通住房
```

具体数值需要经过实际模拟和平衡。

不要机械锁死上述数字，如果测试发现不合理，可以调整。

# 五、核心游戏循环

整个游戏必须围绕一个非常清晰的循环：

```text
查看本周行情
        ↓
判断哪些商品被低估
        ↓
买入
        ↓
决定持有多少现金 / 库存
        ↓
进入下一周
        ↓
商品价格变化
        ↓
卖出盈利 / 止损
        ↓
处理随机事件
        ↓
升级经营能力
        ↓
继续交易
        ↓
购买住房
```

这个循环必须有明显的：

- 风险
- 判断
- 机会成本
- 情绪波动
- “抄底成功”的爽感
- “囤货暴涨”的爽感
- 判断错误造成亏损的压力

不要做成简单点击“下一周”等待数字增长的放置游戏。

# 七、价格模型

这是整个游戏最重要的系统之一。

商品价格应该综合：

```text
基础价格
+
随机波动
+
短期趋势
+
商品自身波动率
+
全局市场环境
+
随机事件
+
价格回归
```

例如可以采用：

```text
P(t+1) =
P(t)
× trend
× randomShock
× eventModifier
× meanReversion
```

但不要为了数学复杂而复杂。

重点是：

玩家观察连续几周价格以后，可以形成一定判断。

价格既不能：

```text
完全随机
```

也不能：

```text
完全可预测
```

理想状态是：

“有规律，但有风险。”

例如：

黄金：

- 波动较小
- 避险事件时上涨
- 相对稳定

显卡：

- 波动非常大
- 可能出现缺货暴涨
- 也可能突然崩盘

猪肉：

- 中等波动
- 受疫情、供应事件影响

空调：

- 明显季节性

羽绒服：

- 冬季需求上涨

# 十、库存系统

玩家不能无限囤积商品。

初始拥有较小的住房/出租屋。

例如：

```text

```

不同商品可以占用不同空间。

例如：

```text
黄金饰品：1
手机：1
大米：2

```

如果加入大型商品，则容量系统尤其重要。

玩家可以花钱：

```text

租仓库
扩大仓库
```

例如：

```text
破旧出租屋
↓
小仓库
↓
普通仓库
↓
大型仓库
```

扩充库存意味着：

当前少一笔现金，

但未来可以抓住更大的交易机会。

这应该形成重要策略选择。

# 十二、随机事件

随机事件是提升重复可玩性的关键。

至少设计：

```text
30～50 个事件
```

不要全部一次性硬编码在逻辑中。

使用数据驱动结构。

例如：

```javascript
{
    id: "chip_shortage",
    title: "芯片供应紧张",
    description: "...",
    duration: 3,
    effects: {
        gpu: 1.6,
        phone: 1.2
    }
}
```

事件类型包括：

### 市场事件

例如：

- 芯片短缺
- 黄金避险需求增加
- 猪肉供应过剩
- 极端高温
- 寒潮
- 物流中断
- 电商促销
- 新产品发布
- 消费低迷

### 个人事件

例如：

- 房东涨租
- 手机坏了
- 公司奖金
- 生病花钱
- 朋友还钱
- 收到红包
- 意外中奖

个人事件不要频繁到让经营策略失去意义。


